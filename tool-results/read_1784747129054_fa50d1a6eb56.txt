   489→# SECTION 20: ANIMATION BLUEPRINT
   490→
   491→## 20.1 Animation Philosophy
   492→
   493→Animations serve communication, not entertainment. Every animation on this platform should reduce cognitive load, not add to it. Animations are used to:
   494→- Orient the user (where did this element come from? where is it going?)
   495→- Confirm interactions (the button responded)
   496→- Signal loading states (something is happening)
   497→- Aid transitions (we're moving to a new context)
   498→
   499→If an animation doesn't serve one of these four purposes, it is not needed.
   500→
   501→## 20.2 Animation Timing
   502→
   503→| Type | Duration | Easing |
   504→|---|---|---|
   505→| Micro-interactions (hover, press) | 150–200ms | `ease-out` |
   506→| Element entrance (fade/slide in) | 250–350ms | `ease-out` |
   507→| Page transitions | 300–400ms | `ease-in-out` |
   508→| Drawers & modals | 300ms | `cubic-bezier(0.4, 0, 0.2, 1)` |
   509→| Skeleton shimmer | 1500ms | Looping linear |
   510→| Breaking ticker scroll | 20–40s (loop) | Linear |
   511→| Live dot pulse | 2s | Looping ease-in-out |
   512→
   513→---
   514→
   515→## 20.3 Page Transitions
   516→
   517→When navigating between pages, the content area performs a quick fade-in (opacity 0→1 over 200ms) as the new page renders. Avoid slide transitions between pages as they can feel disorienting in a content-rich environment.
   518→
   519→On mobile, article open transitions: the article content fades in with a very slight upward translate (8–12px, 250ms). This simulates a "lifting" effect without being theatrical.
   520→
   521→---
   522→
   523→## 20.4 Scroll Animations
   524→
   525→Elements entering the viewport (article cards below the fold, section headings) fade in with a subtle upward translate of 16px over 300ms. This is triggered once — elements do not animate every time they enter the viewport.
   526→
   527→The Breaking News ticker scrolls continuously at a speed calibrated to be readable (~150 pixels per second). It loops seamlessly.
   528→
   529→The Reading Progress bar animates in real-time as the user scrolls — no easing or delay. It must feel perfectly in sync with scroll position.
   530→
   531→---
   532→
   533→## 20.5 Hover Animations (Desktop)
   534→
   535→- **Article card image:** Scale from 1.0 to 1.03 over 300ms. Overflow hidden on the card so the image scales within its container.
   536→- **Article card elevation:** Shadow increases from Level 0 to Level 2 over 200ms.
   537→- **Navigation links:** Underline animates from left to right over 200ms.
   538→- **Buttons:** Background color shift over 150ms.
   539→- **Category badges:** Subtle background fill appears over 150ms.
   540→- **Accordion chevron:** Rotates 180° over 200ms when open/close toggled.
   541→
   542→---
   543→
   544→## 20.6 Loading Animations
   545→
   546→**Skeleton screens:** All card grids, article feeds, and list views show skeleton placeholders while loading. Skeleton elements match the exact layout of real content. A smooth shimmer (a lighter highlight that moves left-to-right) indicates active loading.
   547→
   548→**Image loading:** Use a low-quality blurred placeholder (LQIP) that transitions to full resolution as the image loads. No jarring "pop" of content.
   549→
   550→**Button loading state:** When a form is submitting, the button shows a small inline spinner and its label changes to "Submitting…". The button is disabled during this state.
   551→
   552→---
   553→
   554→## 20.7 Micro-interactions
   555→
   556→- **Search icon tap (mobile):** The overlay slides down from the top with a 250ms ease-out.
   557→- **Share button tap:** Action sheet slides up from bottom (mobile) in 250ms.
   558→- **Audio play/pause:** The play icon transitions to a pause icon with a quick cross-fade, not an abrupt switch.
   559→- **Newsletter subscribe success:** The input field and button transition to a success message — the form elements fade out as the success text fades in.
   560→- **Accordion open:** Height animates from 0 to auto (use max-height technique for CSS, or JS-measured for precision). Content fades in simultaneously.
   561→- **Toast appearance:** Slides in from bottom-right (desktop) or bottom-center (mobile). Slides back out on dismiss.
   562→
   563→---
   564→
   565→## 20.8 Modal & Drawer Animations
   566→
   567→**Modal:** Background overlay fades to 50% opacity (200ms). Modal panel scales from 97% to 100% and fades in (250ms). Combined effect is subtle and elegant.
   568→
   569→**Mobile Drawer (menu):** Slides in from the right edge of the screen over 300ms. Backdrop darkens simultaneously. Swipe-right to close also at 300ms.
   570→
   571→**Bottom Sheet (mobile):** Slides up from the bottom over 300ms. Spring physics are not recommended here — use simple ease-out for a premium, controlled feel.
   572→
   573→---
   574→
   575→## 20.9 Reduced Motion
   576→
   577→All animations respect the `prefers-reduced-motion` media query. When enabled:
   578→- Page transitions are instant (no fade)
   579→- Scroll animations are disabled
   580→- Hover effects are instant (no transition duration)
   581→- Skeleton shimmer is static (no movement)
   582→- Ticker scrolls at half speed or is replaced with a static display
   583→

   588→# SECTION 21: ACCESSIBILITY BLUEPRINT
   589→
   590→## 21.1 Color Contrast
   591→
   592→- All body text on white background: minimum 7:1 contrast ratio (WCAG AA requires 4.5:1; the platform targets the higher AA Large / AAA standard)
   593→- Large text (heading, display): minimum 4.5:1
   594→- UI components (button labels, input borders): minimum 3:1
   595→- Category badges: text on badge background must meet 4.5:1
   596→- Error text on white: must meet 4.5:1
   597→
   598→All contrast ratios to be verified with a tool (e.g., Colour Contrast Analyser) during the design review stage.
   599→
   600→---
   601→
   602→## 21.2 Font Sizing
   603→
   604→- No text smaller than 12px in the published interface (12px is an absolute minimum for micro-labels)
   605→- Body text: 16px minimum on all breakpoints
   606→- Users can scale text using browser zoom — the layout must not break at 200% zoom
   607→- Do not use CSS that prevents text scaling (`-webkit-text-size-adjust: none`)
   608→
   609→---
   610→
   611→## 21.3 Keyboard Navigation
   612→
   613→- Every interactive element (links, buttons, inputs, modals, dropdowns) must be fully operable via keyboard
   614→- Tab order must match the logical visual flow of the page (top-left to bottom-right)
   615→- Modal dialogs must trap focus inside when open
   616→- Dropdown menus must be navigable with arrow keys; Escape closes them
   617→- Skip navigation link: A "Skip to main content" link is the first focusable element on every page, hidden until focused
   618→
   619→---
   620→
   621→## 21.4 Focus States
   622→
   623→- All focusable elements must have a clearly visible focus indicator — the browser's default outline is acceptable but ideally the platform provides a custom focus style (2px solid ring in the brand accent color, 2px offset from element)
   624→- Focus indicators must never be removed with `outline: none` without a custom replacement
   625→- Focus indicators must meet 3:1 contrast ratio against adjacent colors
   626→
   627→---
   628→
   629→## 21.5 Screen Reader Support
   630→
   631→- All images must have meaningful `alt` text. Decorative images use `alt=""`
   632→- The reading progress bar must be marked `aria-hidden="true"` (decorative)
   633→- The Breaking News ticker region must be an `aria-live="polite"` region or updates must be non-disruptive
   634→- Live status indicators ("LIVE", "BREAKING") must convey meaning via text, not color alone
   635→- Audio player controls must have ARIA labels (`aria-label="Play episode"`, etc.)
   636→- Article cards must be implemented as links (`<a>`) wrapping the entire card, or as individual link elements with meaningful link text
   637→- Navigation landmark roles: `<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>` must all be used correctly
   638→- Forms: All inputs must have associated `<label>` elements (not just placeholder text)
   639→
   640→---
   641→
   642→## 21.6 Touch Targets
   643→
   644→- Minimum touch target: 44×44px on all interactive elements
   645→- Targets should have at least 8px spacing between adjacent interactive elements to prevent mis-taps
   646→- The bottom navigation bar items must each have the full height of the bar as a touch target
   647→
   648→---
   649→
   650→## 21.7 Semantic HTML Hierarchy
   651→
   652→- One `<h1>` per page only (the article headline or page title)
   653→- Heading levels never skip (H1 → H2 → H3, not H1 → H3)
   654→- Article body sub-headings use H2 and H3 inside the article `<article>` element
   655→- Lists are marked up with `<ul>` / `<ol>` + `<li>`, never simulated with line breaks
   656→- Tables include `<thead>`, `<tbody>`, `<th scope="col">` for screen reader navigation
   657→
   658→---
   659→
   660→## 21.8 Forms Accessibility
   661→
   662→- Error messages appear adjacent to the relevant field (not just at the top of the form)
   663→- Error messages are announced via `role="alert"` or `aria-live="assertive"` after submission failure
   664→- Required fields are marked with `aria-required="true"` in addition to visual indicators
   665→- Autocomplete attributes are used on common fields (name, email, tel) for assistive technology compatibility

   671→# SECTION 22: PERFORMANCE BLUEPRINT
   672→
   673→## 22.1 Loading Philosophy
   674→
   675→The user's first impression is formed in the first 2 seconds. If the site feels slow in that window, trust is damaged before any content has been read. Performance is a design deliverable, not a technical afterthought.
   676→
   677→## 22.2 Core Web Vitals Targets
   678→
   679→| Metric | Target |
   680→|---|---|
   681→| LCP (Largest Contentful Paint) | < 2.0 seconds |
   682→| FID / INP (Interaction Delay) | < 100ms |
   683→| CLS (Cumulative Layout Shift) | < 0.1 |
   684→| TTFB (Time to First Byte) | < 600ms |
   685→
   686→---
   687→
   688→## 22.3 Image Optimization
   689→
   690→- All images served in modern formats: WebP primary, JPEG fallback
   691→- Responsive images using `srcset` and `sizes` — the browser downloads only the resolution needed for the device
   692→- Hero images: preloaded (`<link rel="preload">`) to improve LCP
   693→- All images below the fold: lazy loaded (`loading="lazy"`)
   694→- No images with intrinsic dimensions left unspecified (always set `width` and `height` attributes to prevent CLS)
   695→- Low-quality image placeholders (LQIP) for perceived performance
   696→
   697→---
   698→
   699→## 22.4 Skeleton Screens
   700→
   701→Every list, grid, and feed shows skeleton placeholder elements during the data fetch. Skeletons:
   702→- Match the exact layout of the real content
   703→- Use an animated shimmer effect
   704→- Never show a spinning loader as a replacement for content layout (spinners cause CLS and feel slower)
   705→
   706→---
   707→
   708→## 22.5 Lazy Loading
   709→
   710→- Images below the fold: `loading="lazy"`
   711→- Comments section (if added): loaded only when user scrolls near it
   712→- Advertisement scripts: loaded asynchronously, deferred until after main content
   713→- Third-party embeds (YouTube, etc.): facade pattern — show a thumbnail with a play button; the iframe only loads when the user clicks play
   714→
   715→---
   716→
   717→## 22.6 Infinite Scrolling vs. Pagination
   718→
   719→- **Homepage Latest News feed:** Infinite scroll (or "Load More" button as a hybrid) — users expect continuous scrolling for news feeds
   720→- **Search results:** Paginated with "Load More" — allows users to maintain position when navigating back from a result
   721→- **Category pages:** "Load More" button preferred — gives users control over the loading moment
   722→- All infinite scroll implementations must include a "You've reached the end" state and "Back to Top" affordance
   723→
   724→---
   725→
   726→## 22.7 Caching Strategy
   727→
   728→- Static assets (CSS, JS, fonts, logo): aggressively cached with long TTL (1 year, with content hash in filename for cache-busting on updates)
   729→- Article pages: short-to-medium cache (5–15 minutes) with stale-while-revalidate pattern
   730→- Breaking news ticker and live updates: no caching (always fresh)
   731→- Homepage: short cache (60–120 seconds) with background revalidation
   732→
   733→---
   734→
   735→## 22.8 Font Loading
   736→
   737→- Use `font-display: swap` for all web fonts to prevent invisible text during load
   738→- Preload the heading font and body font `woff2` files in the document `<head>`
   739→- Limit the number of font files: 2 typefaces maximum, each in 2–3 weights. More fonts = more network requests = slower load.
   740→- System font stack as fallback while web fonts load (ensure the system font is dimensionally similar to the target font to prevent CLS from font swap)
   741→
   742→---
   743→
   744→## 22.9 Third-Party Scripts
   745→
   746→- All third-party scripts (analytics, ads) loaded asynchronously
   747→- No third-party scripts in the critical rendering path
   748→- Ad scripts use `async` and `defer` attributes
   749→- YouTube player uses facade (poster + play button) until interaction — prevents the YouTube iframe from blocking page load
