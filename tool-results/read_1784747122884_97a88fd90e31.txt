  1588→# SECTION 20: ANIMATION BLUEPRINT
  1589→
  1590→## 20.1 Animation Philosophy
  1591→
  1592→Animations serve communication, not entertainment. Every animation on this platform should reduce cognitive load, not add to it. Animations are used to:
  1593→- Orient the user (where did this element come from? where is it going?)
  1594→- Confirm interactions (the button responded)
  1595→- Signal loading states (something is happening)
  1596→- Aid transitions (we're moving to a new context)
  1597→
  1598→If an animation doesn't serve one of these four purposes, it is not needed.
  1599→
  1600→## 20.2 Animation Timing
  1601→
  1602→| Type | Duration | Easing |
  1603→|---|---|---|
  1604→| Micro-interactions (hover, press) | 150–200ms | `ease-out` |
  1605→| Element entrance (fade/slide in) | 250–350ms | `ease-out` |
  1606→| Page transitions | 300–400ms | `ease-in-out` |
  1607→| Drawers & modals | 300ms | `cubic-bezier(0.4, 0, 0.2, 1)` |
  1608→| Skeleton shimmer | 1500ms | Looping linear |
  1609→| Breaking ticker scroll | 20–40s (loop) | Linear |
  1610→| Live dot pulse | 2s | Looping ease-in-out |
  1611→
  1612→---
  1613→
  1614→## 20.3 Page Transitions
  1615→
  1616→When navigating between pages, the content area performs a quick fade-in (opacity 0→1 over 200ms) as the new page renders. Avoid slide transitions between pages as they can feel disorienting in a content-rich environment.
  1617→
  1618→On mobile, article open transitions: the article content fades in with a very slight upward translate (8–12px, 250ms). This simulates a "lifting" effect without being theatrical.
  1619→
  1620→---
  1621→
  1622→## 20.4 Scroll Animations
  1623→
  1624→Elements entering the viewport (article cards below the fold, section headings) fade in with a subtle upward translate of 16px over 300ms. This is triggered once — elements do not animate every time they enter the viewport.
  1625→
  1626→The Breaking News ticker scrolls continuously at a speed calibrated to be readable (~150 pixels per second). It loops seamlessly.
  1627→
  1628→The Reading Progress bar animates in real-time as the user scrolls — no easing or delay. It must feel perfectly in sync with scroll position.
  1629→
  1630→---
  1631→
  1632→## 20.5 Hover Animations (Desktop)
  1633→
  1634→- **Article card image:** Scale from 1.0 to 1.03 over 300ms. Overflow hidden on the card so the image scales within its container.
  1635→- **Article card elevation:** Shadow increases from Level 0 to Level 2 over 200ms.
  1636→- **Navigation links:** Underline animates from left to right over 200ms.
  1637→- **Buttons:** Background color shift over 150ms.
  1638→- **Category badges:** Subtle background fill appears over 150ms.
  1639→- **Accordion chevron:** Rotates 180° over 200ms when open/close toggled.
  1640→
  1641→---
  1642→
  1643→## 20.6 Loading Animations
  1644→
  1645→**Skeleton screens:** All card grids, article feeds, and list views show skeleton placeholders while loading. Skeleton elements match the exact layout of real content. A smooth shimmer (a lighter highlight that moves left-to-right) indicates active loading.
  1646→
  1647→**Image loading:** Use a low-quality blurred placeholder (LQIP) that transitions to full resolution as the image loads. No jarring "pop" of content.
  1648→
  1649→**Button loading state:** When a form is submitting, the button shows a small inline spinner and its label changes to "Submitting…". The button is disabled during this state.
  1650→
  1651→---
  1652→
  1653→## 20.7 Micro-interactions
  1654→
  1655→- **Search icon tap (mobile):** The overlay slides down from the top with a 250ms ease-out.
  1656→- **Share button tap:** Action sheet slides up from bottom (mobile) in 250ms.
  1657→- **Audio play/pause:** The play icon transitions to a pause icon with a quick cross-fade, not an abrupt switch.
  1658→- **Newsletter subscribe success:** The input field and button transition to a success message — the form elements fade out as the success text fades in.
  1659→- **Accordion open:** Height animates from 0 to auto (use max-height technique for CSS, or JS-measured for precision). Content fades in simultaneously.
  1660→- **Toast appearance:** Slides in from bottom-right (desktop) or bottom-center (mobile). Slides back out on dismiss.
  1661→
  1662→---
  1663→
  1664→## 20.8 Modal & Drawer Animations
  1665→
  1666→**Modal:** Background overlay fades to 50% opacity (200ms). Modal panel scales from 97% to 100% and fades in (250ms). Combined effect is subtle and elegant.
  1667→
  1668→**Mobile Drawer (menu):** Slides in from the right edge of the screen over 300ms. Backdrop darkens simultaneously. Swipe-right to close also at 300ms.
  1669→
  1670→**Bottom Sheet (mobile):** Slides up from the bottom over 300ms. Spring physics are not recommended here — use simple ease-out for a premium, controlled feel.
  1671→
  1672→---
  1673→
  1674→## 20.9 Reduced Motion
  1675→
  1676→All animations respect the `prefers-reduced-motion` media query. When enabled:
  1677→- Page transitions are instant (no fade)
  1678→- Scroll animations are disabled
  1679→- Hover effects are instant (no transition duration)
  1680→- Skeleton shimmer is static (no movement)
  1681→- Ticker scrolls at half speed or is replaced with a static display
  1682→

  1687→# SECTION 21: ACCESSIBILITY BLUEPRINT
  1688→
  1689→## 21.1 Color Contrast
  1690→
  1691→- All body text on white background: minimum 7:1 contrast ratio (WCAG AA requires 4.5:1; the platform targets the higher AA Large / AAA standard)
  1692→- Large text (heading, display): minimum 4.5:1
  1693→- UI components (button labels, input borders): minimum 3:1
  1694→- Category badges: text on badge background must meet 4.5:1
  1695→- Error text on white: must meet 4.5:1
  1696→
  1697→All contrast ratios to be verified with a tool (e.g., Colour Contrast Analyser) during the design review stage.
  1698→
  1699→---
  1700→
  1701→## 21.2 Font Sizing
  1702→
  1703→- No text smaller than 12px in the published interface (12px is an absolute minimum for micro-labels)
  1704→- Body text: 16px minimum on all breakpoints
  1705→- Users can scale text using browser zoom — the layout must not break at 200% zoom
  1706→- Do not use CSS that prevents text scaling (`-webkit-text-size-adjust: none`)
  1707→
  1708→---
  1709→
  1710→## 21.3 Keyboard Navigation
  1711→
  1712→- Every interactive element (links, buttons, inputs, modals, dropdowns) must be fully operable via keyboard
  1713→- Tab order must match the logical visual flow of the page (top-left to bottom-right)
  1714→- Modal dialogs must trap focus inside when open
  1715→- Dropdown menus must be navigable with arrow keys; Escape closes them
  1716→- Skip navigation link: A "Skip to main content" link is the first focusable element on every page, hidden until focused
  1717→
  1718→---
  1719→
  1720→## 21.4 Focus States
  1721→
  1722→- All focusable elements must have a clearly visible focus indicator — the browser's default outline is acceptable but ideally the platform provides a custom focus style (2px solid ring in the brand accent color, 2px offset from element)
  1723→- Focus indicators must never be removed with `outline: none` without a custom replacement
  1724→- Focus indicators must meet 3:1 contrast ratio against adjacent colors
  1725→
  1726→---
  1727→
  1728→## 21.5 Screen Reader Support
  1729→
  1730→- All images must have meaningful `alt` text. Decorative images use `alt=""`
  1731→- The reading progress bar must be marked `aria-hidden="true"` (decorative)
  1732→- The Breaking News ticker region must be an `aria-live="polite"` region or updates must be non-disruptive
  1733→- Live status indicators ("LIVE", "BREAKING") must convey meaning via text, not color alone
  1734→- Audio player controls must have ARIA labels (`aria-label="Play episode"`, etc.)
  1735→- Article cards must be implemented as links (`<a>`) wrapping the entire card, or as individual link elements with meaningful link text
  1736→- Navigation landmark roles: `<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>` must all be used correctly
  1737→- Forms: All inputs must have associated `<label>` elements (not just placeholder text)
  1738→
  1739→---
  1740→
  1741→## 21.6 Touch Targets
  1742→
  1743→- Minimum touch target: 44×44px on all interactive elements
  1744→- Targets should have at least 8px spacing between adjacent interactive elements to prevent mis-taps
  1745→- The bottom navigation bar items must each have the full height of the bar as a touch target
  1746→
  1747→---
  1748→
  1749→## 21.7 Semantic HTML Hierarchy
  1750→
  1751→- One `<h1>` per page only (the article headline or page title)
  1752→- Heading levels never skip (H1 → H2 → H3, not H1 → H3)
  1753→- Article body sub-headings use H2 and H3 inside the article `<article>` element
  1754→- Lists are marked up with `<ul>` / `<ol>` + `<li>`, never simulated with line breaks
  1755→- Tables include `<thead>`, `<tbody>`, `<th scope="col">` for screen reader navigation
  1756→
  1757→---
  1758→
  1759→## 21.8 Forms Accessibility
  1760→
  1761→- Error messages appear adjacent to the relevant field (not just at the top of the form)
  1762→- Error messages are announced via `role="alert"` or `aria-live="assertive"` after submission failure
  1763→- Required fields are marked with `aria-required="true"` in addition to visual indicators
  1764→- Autocomplete attributes are used on common fields (name, email, tel) for assistive technology compatibility

  1770→# SECTION 22: PERFORMANCE BLUEPRINT
  1771→
  1772→## 22.1 Loading Philosophy
  1773→
  1774→The user's first impression is formed in the first 2 seconds. If the site feels slow in that window, trust is damaged before any content has been read. Performance is a design deliverable, not a technical afterthought.
  1775→
  1776→## 22.2 Core Web Vitals Targets
  1777→
  1778→| Metric | Target |
  1779→|---|---|
  1780→| LCP (Largest Contentful Paint) | < 2.0 seconds |
  1781→| FID / INP (Interaction Delay) | < 100ms |
  1782→| CLS (Cumulative Layout Shift) | < 0.1 |
  1783→| TTFB (Time to First Byte) | < 600ms |
  1784→
  1785→---
  1786→
  1787→## 22.3 Image Optimization
  1788→
  1789→- All images served in modern formats: WebP primary, JPEG fallback
  1790→- Responsive images using `srcset` and `sizes` — the browser downloads only the resolution needed for the device
  1791→- Hero images: preloaded (`<link rel="preload">`) to improve LCP
  1792→- All images below the fold: lazy loaded (`loading="lazy"`)
  1793→- No images with intrinsic dimensions left unspecified (always set `width` and `height` attributes to prevent CLS)
  1794→- Low-quality image placeholders (LQIP) for perceived performance
  1795→
  1796→---
  1797→
  1798→## 22.4 Skeleton Screens
  1799→
  1800→Every list, grid, and feed shows skeleton placeholder elements during the data fetch. Skeletons:
  1801→- Match the exact layout of the real content
  1802→- Use an animated shimmer effect
  1803→- Never show a spinning loader as a replacement for content layout (spinners cause CLS and feel slower)
  1804→
  1805→---
  1806→
  1807→## 22.5 Lazy Loading
  1808→
  1809→- Images below the fold: `loading="lazy"`
  1810→- Comments section (if added): loaded only when user scrolls near it
  1811→- Advertisement scripts: loaded asynchronously, deferred until after main content
  1812→- Third-party embeds (YouTube, etc.): facade pattern — show a thumbnail with a play button; the iframe only loads when the user clicks play
  1813→
  1814→---
  1815→
  1816→## 22.6 Infinite Scrolling vs. Pagination
  1817→
  1818→- **Homepage Latest News feed:** Infinite scroll (or "Load More" button as a hybrid) — users expect continuous scrolling for news feeds
  1819→- **Search results:** Paginated with "Load More" — allows users to maintain position when navigating back from a result
  1820→- **Category pages:** "Load More" button preferred — gives users control over the loading moment
  1821→- All infinite scroll implementations must include a "You've reached the end" state and "Back to Top" affordance
  1822→
  1823→---
  1824→
  1825→## 22.7 Caching Strategy
  1826→
  1827→- Static assets (CSS, JS, fonts, logo): aggressively cached with long TTL (1 year, with content hash in filename for cache-busting on updates)
  1828→- Article pages: short-to-medium cache (5–15 minutes) with stale-while-revalidate pattern
  1829→- Breaking news ticker and live updates: no caching (always fresh)
  1830→- Homepage: short cache (60–120 seconds) with background revalidation
  1831→
  1832→---
  1833→
  1834→## 22.8 Font Loading
  1835→
  1836→- Use `font-display: swap` for all web fonts to prevent invisible text during load
  1837→- Preload the heading font and body font `woff2` files in the document `<head>`
  1838→- Limit the number of font files: 2 typefaces maximum, each in 2–3 weights. More fonts = more network requests = slower load.
  1839→- System font stack as fallback while web fonts load (ensure the system font is dimensionally similar to the target font to prevent CLS from font swap)
  1840→
  1841→---
  1842→
  1843→## 22.9 Third-Party Scripts
  1844→
  1845→- All third-party scripts (analytics, ads) loaded asynchronously
  1846→- No third-party scripts in the critical rendering path
  1847→- Ad scripts use `async` and `defer` attributes
  1848→- YouTube player uses facade (poster + play button) until interaction — prevents the YouTube iframe from blocking page load
